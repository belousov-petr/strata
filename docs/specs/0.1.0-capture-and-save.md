# Strata 0.1.0: capture and save that hold up in big repos

- Status: implemented in 0.1.0
- Date: 2026-10-03
- Decisions: [ADR-0016](../decisions/ADR-0016-pending-capture-journal.md), [ADR-0017](../decisions/ADR-0017-capture-guard-decides-by-status.md), [ADR-0018](../decisions/ADR-0018-strata-script-for-mechanical-chores.md), [ADR-0019](../decisions/ADR-0019-hot-rules-in-adapters-and-auto-memory-pointer.md)

This is the plan and the spec for the 0.1.0 release. It covers nine changes. Each section says what the change does, which files it touches, how Claude Code and Codex differ, what to watch on Windows, macOS and Linux, and how it is tested.

## Why

The evidence comes from one long session on a large project. That project has a commit gate that takes six to seven minutes, a ban on commits at night, and one git worktree per task. Strata's rules broke down there in a few repeatable ways.

- "Capture immediately" meant writing into tracked `.strata/` files. With a slow commit gate and night bans, the agent either left loose uncommitted files or put the capture off. In the end it kept a parallel log in Claude's private auto memory.
- The hook wrote its inbox in whatever worktree the session started in. Captures scattered across worktrees and disappeared when a worktree was removed.
- The failure hook flagged output that only contained words like "Permission denied" or "exit code 1", even when the command worked. It flagged a successful grep of its own source. In that session it logged 27 captures and none was worth promoting.
- Learnings and the trigger table live in `.strata/memory/`. Subagents and Codex agents never open that folder, so the hot rules never reached them.
- The save contract lists mechanical chores, but the plugin shipped no scripts. Agents did the chores by hand and failed project gates on small mistakes.
- The generated views conflicted on every parallel branch, and "highest id plus one" collided across branches and worktrees.
- Nothing flagged commits that changed the project without a matching decision, doc or issue.

## What ships

- `hooks/strata-capture-guard.mjs` keeps its role as the one hook script shared by Claude Code and Codex. It now decides failures by real status, resolves the shared inbox through the main worktree, and stays quiet unless asked.
- `skills/strata/scripts/strata.mjs` is new. It is a Node script with no dependencies and runs the mechanical chores. Node is the choice because the hook is already Node, and Claude Code and Codex both need Node to run the hook. The script lives inside the skill folder, so every install path ships it: the Claude plugin, the Codex package the marketplace builds from `skills/strata`, and a plain clone.
- Docs: `SKILL.md`, the four commands, `README.md`, `hooks/README.md`, `docs/DESIGN.md`, the scaffold templates, `CHANGELOG.md`, `MIGRATIONS.md`, and four decision records.
- `.github/workflows/test.yml` runs the test suite on Ubuntu, macOS and Windows for every pull request.

### How agents run the script

| Host | Command |
|---|---|
| Claude Code, in a command | `node "${CLAUDE_PLUGIN_ROOT}/skills/strata/scripts/strata.mjs" <subcommand>` |
| Claude Code, in the skill | `node "${CLAUDE_SKILL_DIR}/scripts/strata.mjs" <subcommand>` |
| Codex and other tools | `node <skill folder>/scripts/strata.mjs <subcommand>`, where the skill folder is the one holding `SKILL.md` |

Claude Code substitutes `${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_SKILL_DIR}` in command and skill text when it loads them, so the agent sees an absolute path. The variables are not in the shell environment, so the docs never rely on `$CLAUDE_PLUGIN_ROOT` inside a Bash call.

### Subcommands

| Subcommand | Item | What it does |
|---|---|---|
| `journal add / list / clear` | 1 | Append to, show, or clear the pending-capture journal |
| `status` | 1, 3 | The load-time summary: pending captures, inbox counts by category, repeated failures, view drift |
| `where` | 2 | Print the project root, the shared root, and the inbox path |
| `inbox summary / clear` | 3 | Inbox counts by category and repeated failures; clear after promotion |
| `views [--check]` | 4, 5, 6 | Regenerate ACTIVE, OPEN, PARKED, the learnings INDEX, the MEMORY table, and the hot-rules blocks |
| `views --merge-driver %O %A %B %P` | 6 | The git merge driver for generated views |
| `check [--json]` | 5 | Budgets, vocabularies, ids, links, view drift; exit 1 on errors |
| `save --prepare [--dry-run]` | 5, 8, 9 | Every mechanical save step, then a report of what changed and what needs judgment |
| `setup` | 4, 6 | One-time install: inbox ignore file, merge driver, hot-rules markers |
| `new-issue`, `next-adr` | 7 | Collision-free ids |
| `drift` | 8 | Commits since the last save that no record mentions |
| `pointer` | 9 | Write or refresh the Claude auto-memory pointer |

Every subcommand takes `--root <dir>` (default: the working directory) and prints plain text. The ones a command parses also take `--json`.

### Two roots

The script and the hook resolve two roots.

- The **project root** is the nearest folder at or above the working directory that holds `.strata/`. In a worktree, that is the worktree. Tracked files are read and written here: issues, learnings, views, docs, `CLAUDE.md`, `AGENTS.md`.
- The **shared root** is the main worktree of the same repository, when it also holds `.strata/`. Untracked scratch lives here: the inbox, the journal, the hook cursors, and the small state file. When the folder is not in git, or the main worktree has no `.strata/`, the shared root is the project root.

## 1. Pending-capture journal

**Behaviour.** `/strata:capture` appends one entry to `.strata/inbox/journal.jsonl` under the shared root. That write is instant and needs no commit. The folder is already git-ignored. An entry records:

```json
{"id":"j-20261003-134501-3f2a","ts":"2026-10-03T11:45:01.120Z","kind":"decision",
 "title":"Queue drains before deploy","text":"…","lineage":"supersedes ADR-0007",
 "refs":["src/queue/drain.ts"],"filed":null,"branch":"feat/drain","worktree":"drain"}
```

Kinds are `decision`, `answer` (an operator answer), `finding`, `gotcha`, `learning`, `requirement`, `direction`, `runbook` and `note`. The text comes from `--text` or from stdin, so long text survives shell quoting on every OS. Title, text, lineage and refs pass through the same redaction as the hook before they reach disk. When the agent also files the record right away, `--filed <path>` marks the entry as done so save only checks it.

`/strata:save` reads the journal with `strata journal list --json`, routes every entry into its real store, writes those files in one pass for one commit, and then runs `strata journal clear`. Clear moves the cleared entries to `journal.routed.jsonl`, keeping only the last batch, so a bad routing pass can be redone. `/strata:load` shows "N pending captures" on its first line.

Writers take a short lock file. Clear rewrites the journal through a temp file and a rename, and keeps any line appended while it worked.

**Files.** `skills/strata/scripts/lib/journal.mjs`, `commands/capture.md`, `commands/save.md`, `commands/load.md`, `SKILL.md` §5, §5a, §6, §7.

**Claude and Codex.** Same script, same file. The commands show both invocations.

**Platforms.** Text from stdin avoids quoting differences between bash, zsh, cmd and PowerShell. Paths go through `path.join`. Lines are LF on every OS.

**Tests.** Add, list and clear; redaction of token-shaped values; clear keeps lines appended during the clear; `--filed` entries listed as filed; the journal of a worktree lands in the main worktree.

## 2. One inbox per project across git worktrees

**Behaviour.** The hook and the script resolve the shared root from the working directory without spawning git. They walk up to the nearest `.git`. If it is a file (`gitdir: …/.git/worktrees/<name>`), they read the `commondir` file in that folder to find the common git folder, and the main worktree is the parent of that folder. If the common folder is bare, or the main worktree has no `.strata/`, they fall back to the project root. Outside git, the project root is used. The test suite checks the result against `git rev-parse --git-common-dir` on real worktrees.

When the hook or the script has to create an inbox folder that has no ignore file, it writes `.gitignore` containing `*`, so captures can never show up as untracked files.

The shared state file `.strata/inbox/state.json` holds the last save marker (item 8) and recent id reservations (item 7).

**Files.** `hooks/strata-capture-guard.mjs` (`resolveRoots`), `skills/strata/scripts/lib/core.mjs`.

**Claude and Codex.** Identical. Both pass `cwd` in the hook payload.

**Platforms.** The `gitdir:` line can hold a Windows path with backslashes or a relative path. Both are resolved against the folder that holds the `.git` file.

**Tests.** A real repository with `git worktree add`: a hook payload from the worktree writes to the main inbox; the script's `where` agrees with `git rev-parse --git-common-dir`; a main worktree without `.strata/` falls back; a folder outside git uses the project root.

## 3. Hook noise

**Behaviour.** The hook decides from the real status of a tool result and uses text patterns only where no status exists.

| Source | Status | Decision |
|---|---|---|
| Claude `PostToolUseFailure` (new in `hooks.json`) | always a failure | `failure`, or `interrupted` when `is_interrupt` is true |
| Claude `PostToolUse` | always a success: Claude sends failures to `PostToolUseFailure` | nothing |
| Claude transcript `tool_result` | `is_error` is present on Bash results | `is_error: false` is a success whatever the text says |
| Codex `PostToolUse` | none: the response is a plain string | strict text fallback |
| Codex rollout `function_call_output` | `Process exited with code N` | `N` decides |

Categories:

- `failure`: a shell command that really failed.
- `policy`: a permission refusal. That covers the auto mode classifier ("denied by the Claude Code auto mode classifier", "the auto mode classifier gave no verdict"), "denied by a built-in Claude Code safety check", a harness block, and a user rejecting a tool call. These are not failures.
- `tool-error`: a non-shell tool that returned an error, such as reading a missing file or an edit whose text did not match.
- `interrupted`: a call the user or the harness cut short.

The text fallback is strict. Each pattern is anchored to the start of a line and only the last 60 lines are checked, so a grep or cat that prints the hook's own source no longer matches. The patterns cover shell "command not found", Python tracebacks, `fatal:` from git, npm and pnpm lifecycle failures, TypeScript errors, segmentation faults, Go panics, and the Windows "is not recognized" forms.

The per-failure "capture this now" message is off by default. Set `STRATA_FAILURE_NUDGE=1` to turn it back on. Instead, `strata status` (run by `/strata:load`), `strata save --prepare` (run by `/strata:save`), and the `SessionStart` note report counts by category. Only repeated failures are listed: the same command, or the same signal and output tail, seen at least twice.

Stubs gain a `category` field and, when the host gives one, `tool_use_id`. A stub keyed by `tool_use_id` is never logged twice, so the live event and the transcript scan agree. Old stubs without a category are read as `failure`, or as `policy` when their text matches a refusal.

Inbox clear no longer deletes cursor files. Deleting them made the next scan re-read old transcripts and log promoted failures again. Clear now prunes only cursors whose transcript is gone or that are older than 30 days.

**Files.** `hooks/strata-capture-guard.mjs`, `hooks/hooks.json`, `hooks/codex-hooks.sample.json` (comment only), `hooks/README.md`, `skills/strata/scripts/lib/inbox.mjs`.

**Claude and Codex.** Claude gains `PostToolUseFailure` with matcher `Bash`. Codex has no such event, so its `PostToolUse` keeps the strict fallback and its per-turn `Stop` scan reads exit codes from the rollout. Codex still has no `SessionEnd`.

**Platforms.** Windows shells print "is not recognized" errors, which the fallback covers. Nothing else in this item depends on the OS.

**Tests.** Recorded transcript samples under `tests/fixtures/`, written by hand to match real structure with no real secrets or paths: a Claude session with a successful grep of the hook source, real exit-code failures, classifier refusals, a safety-check refusal, a harness block, a missing-file read and an interrupt; a Codex rollout with exit codes 0, 1 and 2. Each sample asserts its counts per category. Entry-point tests for `PostToolUseFailure`, silent `PostToolUse` success, the opt-in nudge, and `tool_use_id` dedupe across the live event and the scan.

## 4. Hot rules reach every agent

**Behaviour.** Subagents and Codex load `CLAUDE.md` and `AGENTS.md` but never open `.strata/memory/`. Strata now keeps a generated block in both adapters:

```markdown
<!-- strata:hot-rules:begin -->
## Hot rules from strata

Generated from `hot: true` learnings by strata. Edit the learning files, not this block.

- **Before pushing to a shared branch:** Run the repo lint first. ([rule](.strata/memory/learnings/push-lint.md))
<!-- strata:hot-rules:end -->
```

One line per hot learning: the trigger, the first sentence of the lesson, and a link. The set is the same hot subset the `MEMORY.md` table uses, including the graceful default for projects with no `hot:` flag. The block has a budget of 25 rules and 4,000 characters. Past that, it lists what fits in trigger order, adds a line saying how many more sit in `MEMORY.md`, and save reports the overflow.

`strata views` and `strata save --prepare` rewrite only the text between the markers, in each adapter that already has them. Text outside the markers is never touched. `strata setup`, run by `/strata:init`, adds the markers to the end of an existing adapter. New projects get the markers from the templates.

**Files.** `skills/strata/scripts/lib/adapters.mjs`, `templates/CLAUDE.md`, `templates/AGENTS.md`, `SKILL.md` §4 and §8.

**Claude and Codex.** Claude reads `CLAUDE.md`, Codex reads `AGENTS.md`, and recent Claude Code versions read both. The block is kept small for that reason.

**Platforms.** The script keeps the line endings the file already uses.

**Tests.** Markers rewritten and nothing outside them changed; no markers means no change; budget overflow; legacy projects with no `hot:` flag; the scaffold renders with no drift.

## 5. Deterministic save chores

**Behaviour.** `strata save --prepare` does every mechanical step and prints a report in two parts: what it changed, and what needs judgment.

Changes it makes:

1. Move `resolved` and `wont-fix` issues to `issues/archive/`, with `git mv` when tracked. Each move adds a row to `issues/archive/INDEX.md`, which new projects get from the templates and older ones get on first use. `git mv` carries uncommitted edits along, which matters because the save itself usually sets the status, so such moves go ahead and the report flags them. A file with an unresolved merge conflict is skipped.
2. Roll `project_state.md` sessions older than the two newest into `memory/archive/YYYY-MM-sessions-<first>-<last>.md` and add a row to `ARCHIVE.md`. Session blocks are `##` headings that carry a session number. When no numbers can be read, nothing moves and the report says so.
3. Regenerate the views: ACTIVE, OPEN, PARKED, `learnings/INDEX.md`, the `MEMORY.md` rules table, and the hot-rules blocks (items 4 and 6).
4. Refresh the auto-memory pointer (item 9) and the merge driver path when the driver is installed (item 6).
5. Record the save marker (item 8).

Judgment items in the report: pending journal entries, inbox counts and repeated failures, the drift list (item 8), check findings, the `MEMORY.md` budget, parked items to review against their `revive-when:`, and skipped moves. `strata status`, run first by `/strata:load`, also says when a project still lacks the 0.1.0 add-ons.

`--dry-run` prints the same report without writing. `/strata:save` runs the dry run for its preview, then the real run after its own writes.

`strata check` validates without writing:

- the `layout_version: 3` stamp
- `MEMORY.md` at most 80 lines, `project_state.md` at most 200
- issue frontmatter: required fields, the type, status and severity vocabularies, the id format, ids unique across live and archived issues, `revive-when:` on parked items, and terminal items still outside `archive/` as a warning
- learning frontmatter: a trigger, an origin from the vocabulary, `hot` true or false
- relative links in `.strata/**/*.md` that do not resolve
- generated views and hot-rules blocks that differ from a fresh render
- archive files missing from `ARCHIVE.md`, as a warning

It exits 1 on errors and 0 on warnings only.

A project that renders its own views can set `generated_views: external` in the `MANIFEST.md` frontmatter. Then `views` and `save --prepare` leave the views alone, and `check` skips view drift.

**Files.** `skills/strata/scripts/strata.mjs`, `lib/frontmatter.mjs`, `lib/views.mjs`, `lib/check.mjs`, `lib/save.mjs`, `commands/save.md`, `SKILL.md` §6, `templates/issues/archive/INDEX.md`.

**Claude and Codex.** Same script.

**Platforms.** Pure Node with `node:` modules only. Git runs through `spawnSync` with an argument list, never a shell string. CRLF files are read and written back as CRLF. CI runs the tests on all three systems.

**Tests.** Rendering is stable, sorted and idempotent, and keeps each view's header; a fresh scaffold has no drift; archive moves with index rows, including a file with uncommitted edits; session rollover with an `ARCHIVE.md` row; each check finding; the dry run writes nothing.

## 6. Merge-friendly generated views

**Behaviour.** Row order is deterministic. ACTIVE and OPEN sort by severity (high, med, low, then anything else), then id, then file name. OPEN groups by area in alphabetical order. PARKED sorts by id. INDEX and the `MEMORY.md` table sort by trigger, then file name.

`strata setup` adds this block to `.gitattributes`:

```
# >>> strata generated views (merge by rows; /strata:save regenerates them)
.strata/issues/ACTIVE.md merge=strata-views
.strata/issues/OPEN.md merge=strata-views
.strata/issues/PARKED.md merge=strata-views
.strata/memory/learnings/INDEX.md merge=strata-views
.strata/memory/MEMORY.md merge=strata-views
/CLAUDE.md merge=strata-views
/AGENTS.md merge=strata-views
# <<< strata generated views
```

The adapters are in the list because their hot-rules block (item 4) changes on parallel branches too.

It also sets the driver in the repository's local git config, which is shared by all worktrees of that clone. The one-time line, for a clone where `setup` did not run, is:

```
git config merge.strata-views.driver "node <path to strata.mjs> views --merge-driver %O %A %B %P"
```

During a merge, the item files are not yet in the working tree, so the driver cannot simply regenerate from them. It does a three-way merge of table rows (and of hot-rules lines in the adapters) keyed by issue id or learning file instead: a row added on either side is kept, a row deleted on one side and unchanged on the other is dropped, and a row changed on one side takes that change. It renders the merged rows in the deterministic order, then lets `git merge-file` merge any hand-written text around the table, such as the live pointers in `MEMORY.md`. The next `strata views` makes the views exact. When the driver is not configured, git falls back to its normal text merge. `save --prepare` refreshes the driver path after a plugin update moves the script.

**Files.** `lib/views.mjs`, `lib/setup.mjs`, `SKILL.md` §8, `commands/init.md`.

**Claude and Codex.** Not host specific.

**Platforms.** The driver line uses forward slashes, which Git for Windows accepts, and quotes paths that hold spaces.

**Tests.** End-to-end merges in real repositories with the driver configured: two branches each adding an issue; one branch resolving an issue while the other adds one; two branches each adding a hot learning while one also edits a live pointer in `MEMORY.md`, with `CLAUDE.md` and `AGENTS.md` merging cleanly too. After each merge `strata views --check` passes. A clone without the driver falls back to a plain text merge, `check` warns about the missing driver, and `save --prepare` refreshes a driver line that points at an old plugin path.

## 7. Collision-free issue ids

**Behaviour.** `strata new-issue --slug <slug> [--type --severity --area --status --title]` picks the next id for the day and writes the issue from `_TEMPLATE.md`. Before choosing, it collects the day's ids from:

- the project tree, including `issues/archive/`
- every worktree from `git worktree list --porcelain`
- every local and remote-tracking branch whose tip is no older than two days: `git for-each-ref` and then `git ls-tree` on `.strata/issues/`
- reservations in the shared state file, which cover two sessions allocating at the same moment

The new id is the highest of those plus one. `--dry-run` prints the id without writing. `strata next-adr` does the same scan for decision records and prints the next number.

**Files.** `lib/ids.mjs`, `commands/capture.md`, `commands/save.md`, `SKILL.md` §3 and §6.

**Tests.** An id used only on another branch is skipped; an id used only in another worktree's uncommitted file is skipped; a reservation is skipped; the first issue of the day is `-01`.

## 8. Docs and decision drift check at save

**Behaviour.** The save marker is the commit recorded by the last `save --prepare` in the shared state file. When that commit is missing or no longer an ancestor of HEAD, the marker is the last commit that touched `.strata/memory/project_state.md`. When there is neither, the check looks at the last 20 commits.

`strata drift` lists the first-parent commits and merges after the marker, at most 200. It skips commits that change only `.strata/`. A commit counts as referenced when any of these holds:

- its message names an issue id or decision number that exists
- its short hash or, for a merge, its branch name appears in a record
- one of its changed paths, or that path's parent folder, appears in a record

The records are the decision records, the docs, issues (live and archived), learnings, `CHANGELOG.md`, and pending journal entries. Unreferenced commits form the drift list, which shows up in the save report as at most 15 lines.

**Files.** `lib/drift.mjs`, `commands/save.md`.

**Tests.** A repository with one commit that a decision record mentions and one that nothing mentions: only the second is listed; a merge commit is matched by its branch name; the marker moves after a save.

## 9. Claude auto-memory pointer

**Behaviour.** The rule: Claude Code's auto memory holds only a pointer to `.strata/`. `/strata:save`, through `save --prepare`, writes or refreshes `strata-pointer.md` in the project's auto-memory folder and keeps one line for it in that folder's `MEMORY.md`. It never writes anything else there and never touches other lines. When the folder does not exist, it does nothing and says nothing.

The folder is `<config dir>/projects/<encoded path>/memory/`. The config dir is `CLAUDE_CONFIG_DIR` or `~/.claude`. The encoded path is the main worktree path with every character that is not a letter or digit replaced by `-`, which is what Claude Code uses, and auto memory is shared by all worktrees of a repository. Paths longer than 200 characters carry a hash suffix that strata cannot rebuild, so it looks for a folder whose name starts with the first 200 characters. `CLAUDE_CODE_PROJECT_DIR_NAME` replaces the encoded path when `CLAUDE_CONFIG_DIR` is set. A custom `autoMemoryDirectory` setting is not detected, and then the step is skipped. `STRATA_AUTO_MEMORY_POINTER=0` turns the step off.

**Files.** `lib/pointer.mjs`, `SKILL.md` §11, `commands/save.md`, `README.md`.

**Claude and Codex.** Claude only. Codex has no equivalent folder to point from.

**Platforms.** Uses `os.homedir()`. Windows paths encode the same way, so `C:\work\app` becomes `C--work-app`.

**Tests.** A fake config dir: pointer written and the index line added once; a second run changes nothing; other lines are left alone; a missing folder is skipped; the opt-out works.

## Compatibility and migration

No layout change. Projects stay on `layout_version: 3` and need no migration rung. Everything new is additive:

- the journal and state file live in the git-ignored inbox
- `issues/archive/INDEX.md` is created on first use
- the `.gitattributes` block and the adapter markers come from `strata setup`
- `generated_views` is an optional frontmatter key

After updating the plugin, a project runs `/strata:init` once. On a project that already has the current layout, init no longer stops at "already initialized". It runs `strata setup`, which adds the merge driver and the hot-rules block, and changes nothing else. Each additional clone runs `strata setup` once, or the one-time `git config` line, because git config is not committed.

`/strata:save` regenerates the views in strata's format. A project that keeps its own generator sets `generated_views: external`.

## Cut back or left out

- The merge driver merges rows instead of regenerating from item files, because the merged item files do not exist in the working tree while git runs a driver. `strata views` at the next save makes the views exact.
- The auto-memory pointer cannot see a custom `autoMemoryDirectory` setting.
- The drift check matches on paths, folder names, hashes, branch names and ids. It does not read diffs, so a commit that a record describes only in prose shows up as drift.
